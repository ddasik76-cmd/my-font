# 나의 글씨

한글 초성·중성·종성 67개와 영문·숫자·기호 94개를 직접 쓰고, 현대 한글 11,172자를 포함한 OTF를 생성하는 반응형 웹앱입니다. 원본은 IndexedDB에 저장하며 서버에 업로드하지 않습니다.

## 실행

Node.js 22.12 이상(검증 환경 24.18)이 필요합니다.

```sh
npm ci --ignore-scripts
npm run dev
```

기본 주소는 http://localhost:5173 입니다. 포트가 사용 중이면 터미널에 표시된 다음 포트를 이용하세요. 로컬 개발 서버는 공개 배포 주소가 아닙니다.

```sh
npm run build
npm test
npm run test:e2e
```

E2E는 설치된 Microsoft Edge를 사용하고 5175 포트에서 테스트 서버를 실행합니다. `mobile` 테스트는 iPhone 화면 크기·터치 환경을 에뮬레이션한 Chromium 테스트이며 iOS Safari 실기기 테스트가 아닙니다.

## 사용 순서

1. 새 프로젝트에 폰트 이름을 지정합니다.
2. 초성 19 → 중성 21 → 종성 27 → 영문 52 → 숫자 10 → 기호 32개를 입력합니다.
3. 미리보기 화면에서 문장을 입력하고 폰트를 생성합니다. 일부 입력 상태에서는 그릴 수 있는 글자만 미리 봅니다.
4. 161개를 모두 작성한 후 전체 폰트를 생성하면 OTF 다운로드가 활성화됩니다.
5. 미리보기는 문장에 필요한 문자만 만들며 OTF/TTF 렌더링을 선택할 수 있습니다. 다운로드는 161개 입력을 완료한 뒤 TTF, OTF 또는 두 형식을 생성해 각각 받을 수 있습니다.
6. 원본 백업 JSON으로 다른 기기에 옮기거나 복원합니다. 복원은 새 프로젝트로 생성되어 기존 프로젝트를 덮어쓰지 않습니다.

입력한 자모를 위치별로 재배치하는 방식이며 AI 필체 예측은 사용하지 않습니다. 조합형 글꼴의 자연스러움은 원본 자모 형태에 영향을 받습니다. 크기와 위치를 조절해 개선할 수 있습니다. 전체 음절을 다시 쓰도록 요구하지 않습니다.

## 구조

- `src/charset.ts`: 161개 과제와 한글 분해·의존성
- `src/font.ts`: 획 외곽선, 겹침 병합, 자모 배치, OTF 생성·재파싱
- `src/font.worker.ts`: UI와 분리한 폰트 생성, 진행률
- `src/storage.ts`: IndexedDB, revision 충돌 감지, 백업 검증
- `src/components/`: 필기 캔버스와 획 미리보기
- `src/App.tsx`: 작업실·편집·미리보기·다운로드·설치 안내
- `src/styles.css`: 참고 이미지의 그라데이션·패널과 반응형 스타일
- `tests/`: 브라우저에서 필기·복원·다운로드·모바일 레이아웃 검증

생성 OTF와 TTF에는 한글 11,172자, ASCII 95자(공백 포함), 호환 자모 51자가 매핑됩니다. `.notdef`를 포함하면 글리프 수는 11,319개입니다. TTF는 OTF 윤곽을 TrueType 윤곽으로 변환하고 문자 매핑을 재검증합니다. 옛한글·한자·이모지는 지원하지 않으며 미리보기에서 대체 글꼴을 명시합니다. 앱 내부 문장은 NFC 정규화합니다. 외부 앱의 NFD 조합은 별도 검증이 필요합니다.

## Vercel 배포

`vercel.json`에 빌드·SPA 새로고침·보안 헤더를 설정했습니다. 서버/API 키는 필요하지 않습니다.

1. 이 폴더의 소스를 GitHub 저장소로 올립니다. `.env`, 원본 백업, `artifacts`, 자격증명은 업로드하지 않습니다.
2. Vercel에서 저장소를 Import하고 Vite 프로젝트로 선택합니다.
3. Build Command `npm run build`, Output Directory `dist`를 확인합니다.
4. 프리뷰 배포 후 URL 직접 진입, Worker 생성, 폰트 다운로드를 확인합니다.
5. 프로덕션 URL을 공개하고 실제 Galaxy와 iPhone에서 확인합니다.

미리보기에서 작업 제한 시간이 지나면 원본 필기를 보존하고 다시 시도할 수 있도록 안내합니다. 브라우저 글꼴 로딩은 파일 생성·검증과 별도 상태로 처리합니다. 공개 도메인을 바꾸면 브라우저 저장소도 달라지므로 이전 주소에서 백업을 먼저 받아야 합니다.

## 검증 범위와 남은 작업

자세한 결과는 `VALIDATION.md`에 기록합니다. 실제 Galaxy/iPhone에서 파일 저장 및 외부 문서 앱 사용, Windows/macOS의 OS 설치 UI까지는 별도 확인이 필요합니다. 생성 파일을 Windows 글꼴 파서가 읽는 것과 실제 OS 설치는 구분합니다.

AI 보완·사진 업로드·계정 동기화·자모 유형별 추가 변형은 후속 범위입니다. 웹사이트의 파일 다운로드가 휴대폰 전체 시스템 글꼴 변경을 의미하지 않습니다.

## 의존성 및 개인정보

정확한 버전은 `package-lock.json`으로 고정합니다. 설치 시 스크립트를 비활성화했고 npm audit에서 알려진 취약점 0건을 확인했습니다. 감사 결과가 모든 공급망 위험의 부재를 보장하지는 않습니다. 주요 의존성 라이선스는 `THIRD_PARTY_NOTICES.md`를 참고하세요.

외부 글꼴/CDN/분석 SDK를 사용하지 않습니다. 제작 데이터는 현재 브라우저의 IndexedDB에만 저장됩니다. 브라우저 데이터를 삭제하면 백업이 없는 작업은 복구할 수 없습니다. 저장 실패·다른 탭의 수정 충돌 발생 시 원본 백업을 다운로드해 보관하세요.
